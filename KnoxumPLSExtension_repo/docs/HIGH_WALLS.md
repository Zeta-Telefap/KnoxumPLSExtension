# HighWalls — как это работает

Вся фича живёт в одном файле: `src/Features/HighWalls.cs` (~1430 строк).

## Ключевое решение: тайл поднимается, стены растут вверх

В старых WIP-вариантах тайл поднимался наверх комнаты, а стены достраивались **вниз**.
Это ломает всё остальное, потому что:

- двери — дети `tile.ObjectBase` (`EnvironmentController.SetupDoor`, стр. 70630);
- лампы — дети `TileTransform` (стр. 85460);
- постеры, доски, кнопки — тоже дети тайла.

То есть всё содержимое комнаты едет вместе с тайлом. Если поднять тайл наверх,
двери и объекты окажутся под потолком.

Поэтому в `HighWalls.cs`:

```
пол комнаты   = yOffset * 10        ← тайл стоит здесь, вместе с дверьми/объектами/лампами
стены [0..10] = запечённый меш тайла (ванильный, с дверными проёмами и окнами)
стены [10..H*10] = сгенерированные слои (H = height)
потолок       = H*10                ← свой меш, у тайла потолок вырезается
юбка [-O*10..0] = сгенерирована, если O = yOffset > 0
```

## Почему именно так, а не «двигать весь RoomController»

`Cell.FloorWorldPosition` и `Cell.CenterWorldPosition` (стр. 56602 / 56612) —
**захардкоженные координаты сетки** с `y = 0` и `y = 5`. По ним спавнятся игрок,
NPC, предметы и триггеры, и они **не смотрят на позицию тайла**.

Следствия:
1. Высота стен (`height`) полностью безопасна: контент остаётся на полу.
2. Подъём комнаты (`yOffset`) двигает только геометрию и детей тайла —
   игрок и NPC при спавне останутся на `y = 5`. Это **известное ограничение**,
   чинить его надо отдельным патчем этих двух свойств (и навигации), поэтому
   `yOffset` считается экспериментальным.

## Точки интеграции

| Что | Метод | Зачем |
|---|---|---|
| Редактор | `EditorController.RefreshCells` (Postfix) | вызывается при любом изменении ячеек |
| Рантайм | `EnvironmentController.CreateCell(int, Transform, IntVector2, RoomController, bool, bool)` (Postfix) | единственное место, где ячейка уже получила комнату, форму и тайл |
| Подсветка | `EditorController.HighlightCells` / `UnhighlightAllCells` (Postfix) | синхронизация `_LightMap` нашей геометрии с плиткой |
| Текстуры | `RoomSettingsExchangeHandler.UpdateTextures` (Postfix) + `RoomController.GenerateTextureAtlas()` (Postfix) | перекраска после смены текстур комнаты |
| Сохранение | `EditorLevelData.Write` / `ReadFrom` (Postfix) | .ebpl **и undo** — один и тот же путь (undo = сериализация, стр. 133060) |
| roomId → рантайм | `EditorLevelData.Compile` / `EditorController.Compile` (Postfix) | в имя комнаты дописывается `#KHW:<id>` |

## Формат данных в сейве

После штатных данных `EditorLevelData` дописывается блок:

```
uint32 magic = 0x57484B6B
uint16 version = 1
int32  count
  повтор count раз: int32 roomId, int32 height, int32 yOffset, bool skirt
```

При чтении, если magic не совпал, поток отматывается назад, а настройки очищаются —
уровни, сохранённые без мода, открываются как обычно.

## Материалы

- Шаблон — `room.baseMat` (`wallMat/floorMat/ceilingMat` в BB+ **не инициализированы**, стр. 106605).
- `_MainTex` — атлас **конкретной комнаты**. В редакторе нельзя брать `workerRc.baseMat`:
  в цикле `RefreshCells` он перезаписывается каждой комнатой, поэтому атлас запрашивается
  через `EditorController.GenerateTextureAtlas(floor, wall, ceil)` (внутри есть кэш по текстурам).
- `_LightMap` копируется с материала плитки — иначе стены светятся иначе, чем пол.
- Один материал на ячейку, не на каждый кусок стены.

## UV-квадранты атласа

```
потолок u[0..0.5] v[0.5..1]   |   стена u[0.5..1] v[0.5..1]
пол     u[0..0.5] v[0..0.5]   |   (пусто)
```

Тайлить текстуру стены по вертикали через атлас **нельзя** (Repeat вылезет в соседний
квадрант), поэтому каждый слой стены — отдельный квад, берущий весь квадрант стены.

## Управление

- `F8` в редакторе — оверлей со списком комнат: **Высота** (1..8 слоёв), **Подъём** (0..8),
  галка **Юбка под полом**, кнопка пересборки геометрии.
- Изменения пишутся в undo (`EditorController.AddUndo`) и сохраняются в `.ebpl`.

## Проверка API (что именно све́рено, а не «должно работать»)

Файл **не собирался** — в песочнице нет компилятора (см. ниже). Вместо этого каждый
внешний вызов све́рен с первоисточником:

| Источник | Что проверено | Результат |
|---|---|---|
| `ultimate_dev_mods_decompile.cs` | 37 типов/членов игры, PLS и формата уровня (полный список в `docs/DECOMPILE_ANALYSIS.md`) | все 37 найдены с подходящими сигнатурами |
| `ultimate_dev_mods_decompile.cs` | `EditorController.Compile()` объявлен ровно 1 раз (стр. 133792) | нет «ambiguous match» в Harmony |
| `ultimate_dev_mods_decompile.cs` | `RoomSettingsExchangeHandler.UpdateTextures()` — без аргументов | патч корректен |
| BepInEx 5.4.21 (исходники) | `BepInPlugin(string, string, string)`, `ConfigFile.Bind<T>(section, key, default, string description)` (стр. 312), `BaseUnityPlugin.Config`, `.Logger` | совпадает |
| Harmony 2 (исходники) | `HarmonyPatch(Type, string)` и `HarmonyPatch(Type, string, params Type[])`, `Harmony.PatchAll()` | совпадает |

**Почему нет компиляции.** В песочнице только частичный доступ в сеть: отвечают
`github.com`, `codeload.github.com`, `pypi.org`; заблокированы `nuget.org`,
все CDN Microsoft (`builds.dotnet.microsoft.com`, `download.visualstudio.microsoft.com`),
`deb.debian.org`. То есть ни .NET SDK, ни Mono, ни пакеты NuGet скачать нельзя —
референсные сборки Unity тем более. Проверка компиляцией возможна только на машине с игрой.

## Известные ограничения

1. `yOffset` не поднимает игрока/NPC (см. выше) — только геометрию.
2. Нет проёмов в юбке у дверей и нет учёта `WindowLocation` на верхних слоях —
   заготовка в `HighWallsBuilder.ShouldBuildWall`.
3. UI — временный IMGUI-оверлей, а не нативный UI PLS (`EditorInterface` / `UIExchangeHandler`).
4. Файл не собирался (в песочнице нет ни Unity, ни сборок игры) — проверена только
   синтаксическая целостность и соответствие API по декомпиляции.
